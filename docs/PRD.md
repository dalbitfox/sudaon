# OnChat 제품 요구사항 문서

- 버전: 1.0 — 인터뷰 완료, 개발 기준안
- 작성일: 2026-10-30 (한국 시간)
- 상태: 핵심 사용 흐름 및 개인·비상업적 용도 확정. Vercel 무료 구성을 우선 검증하고 실측 결과에 따라 운영 방식을 결정.
- 이 문서는 제품 설계이며, 구현·배포·200명 성능 검증 완료를 뜻하지 않는다.

## 1. 제품 목적

발표 중 청중이 QR로 접속해 별명만 입력하고 자유롭게 대화한다. 발표자는 PowerPoint, Excel, 웹브라우저로 자료를 보여주면서 그 위에 실시간 채팅과 인기 키워드를 함께 공개한다. 청중 참여는 모바일 웹을 중심으로 하고, 발표 화면 제어는 Windows 앱이 담당한다.

## 2. 인터뷰로 확정한 요구사항

| 항목 | 결정 |

| 키워드 표시 | 인기 단어 순위와 워드클라우드 모두 제공, 전환 가능 |

| 비용 방향 | Vercel 무료 플랜 사용 가능 여부를 먼저 확인하고, 불가하면 발표자 PC 로컬 방식 |

다음 절의 수치·세부 동작·기술 선택은 구현을 구체화하기 위한 **권장 초깃값**이며, 사용자가 별도로 선택한 확정 답변과 구분한다.

## 3. 구현 방식과 운영 결정

### 3.1 공통 제품 구성

1. 청중: 설치 없는 반응형 웹. Android Chrome·iPhone Safari를 검증 대상으로 한다.
2. 발표자: Windows 데스크톱 앱. 관리 화면과 공개 표시창을 분리한다.
3. 표시창: 통합 1개 또는 채팅·키워드 2개. 여러 창이 동일 데이터를 공유한다.
4. 서버: 방·참여 세션·메시지·권한·키워드 집계의 기준 상태를 관리한다.
5. 저장소: 발표 기록과 통계를 재시작 후에도 복원하고 Excel로 내보낸다.

데스크톱 앱은 클라우드 방식에서도 필요하다. 서버 위치와 Windows 창 고정·투명도 제어는 별개의 선택이다. 웹의 Document Picture-in-Picture는 보조 경로로만 검토하며 필수 표시창 기능을 대체하지 않는다. [Chrome 문서](https://developer.chrome.com/docs/web-platform/document-picture-in-picture)

### 3.2 1순위: Vercel 무료 구성의 조건부 검증

- Vercel은 현재 모든 플랜에서 WebSocket을 지원한다. 연결은 함수 최대 실행 시간에 종료되며, 다른 인스턴스로 재연결될 수 있다. 방 상태·이력·인스턴스 간 배포는 외부 저장소에서 공유해야 한다. [공식 WebSocket 문서](https://vercel.com/docs/functions/websockets)
- Hobby 무료 한도와 개인·비상업적 사용 조건을 확인한다. 구체적인 조사 결과는 [운영 검토서](./HOSTING_REVIEW.md)에 기록한다. [Hobby 문서](https://vercel.com/docs/plans/hobby)
- 후보: Vercel 웹/API/WebSocket + 무료 외부 저장소·인스턴스 간 동기화 계층 + Windows 표시 앱.
- 외부 서비스의 무료 한도도 포함해 총비용을 평가한다. Vercel 무료만으로 영구 기록 저장까지 해결된다고 가정하지 않는다.
- 외부 저장소와 동기화 제품은 사전 실험에서 확정한다. 지속 저장, 원자적 메시지 순번, 중복 방지, 여러 함수 인스턴스 간 전파, 한도 계측을 모두 지원해야 한다.
- 무료 조건 적합성과 200명 검증을 모두 통과하면 채택한다. 실제 계정의 기존 사용량은 별도 확인 대상이다.

### 3.3 대안: Windows 로컬 서버

- Windows 앱이 로컬 채팅 서버·모바일 웹·SQLite 저장소를 함께 실행한다.
- 청중의 휴대폰 데이터 접속을 유지하려면 공개 HTTPS/WSS 주소로 로컬 서버를 연결하는 터널 또는 별도 공개 네트워크 구성이 필요하다.
- `localhost`나 사설 IP를 QR에 넣는 것만으로 외부 청중이 접속할 수는 없다.
- 임시 터널은 소규모 개발 검증 후보이며, 정식 행사에서 200명 접속을 보장하는 수단으로 채택하지 않는다.
- 터널의 상업적 사용 조건, 연결·전송량 제한, 주소 유지, 장애 복구를 조사한 후 선택한다. 무료 터널이 요구사항을 충족하는지는 미확정이다.
- 행사 중 서버 PC·터널 종료 또는 절전 시 청중 접속도 중단된다. 표시창 숨기기와 서버 종료를 구분하고 앱에서 서버·터널 상태를 확인한다.
- 클라우드 실패 시 행사 도중 자동으로 로컬로 옮기는 기능은 초기 범위에 넣지 않는다. 행사 전에 운영 방식을 선택하며 주소가 바뀌면 QR도 새로 만든다.
- 로컬도 검증에 실패하면 200명 지원을 완료로 표시하지 않는다. 유료 전환이나 동일 Wi-Fi 전용으로 요구사항 변경은 사용자와 별도 결정한다.

## 4. 사용자와 권한

### 발표자

- 방 생성·시작·종료, QR 표시, 채팅 관리, 표시창 설정, 과거 기록 조회·다운로드.
- 클라우드 운영 시 단일 운영자 인증을 적용하고 공개 회원가입을 제공하지 않는다. 인증 수단은 사전 실험에서 확정한다.
- 로컬 운영 시 운영 권한은 로컬 관리 화면에 한정한다. 외부 주소에서는 청중용 경로만 열고 관리 API는 인증 없이 접근할 수 없도록 한다.

### 청중

- 열린 방에 별명으로 입장, 메시지 전송, 공개 대화 조회, 나가기.
- 방 생성·다른 방 기록 조회·종료 후 기록 다운로드·다른 사람 메시지 삭제 권한 없음.
- 별명은 표시 이름이다. 서버가 발급한 참여 세션으로 본인을 식별하고, 별명만으로 권한을 판단하지 않는다.

## 5. 주요 사용 흐름

### 발표 준비

앱 실행 → 서버 연결 상태 확인 → 발표 제목으로 새 방 생성 → QR 및 접속 링크 생성 → QR을 청중에게 표시 → 표시창 위치·크기·투명도 설정 → 발표 시작.

### 청중 참여

휴대폰 카메라로 QR 스캔 → 방 제목 및 공개 채팅·기록 보관 안내 확인 → 별명 입력 → 입장 → 실시간 대화.

연결 중·실패·정원 초과·종료된 방을 구분해 안내한다. 서버 연결을 확인하기 전 입장 완료로 표시하지 않는다.

### 발표 중

메시지가 모든 청중 화면과 발표 표시창에 반영된다. 키워드는 일정 주기로 갱신된다. 운영자는 공개 방식의 사전 승인 없이 필요한 메시지 삭제·참여자 내보내기를 수행한다.

### 발표 종료

종료 확인 → 신규 입장·메시지 전송 차단 → 연결된 청중에게 종료 안내 → 기록·최종 키워드 집계 보존 → 운영자 기록 화면에서 다시 보기·Excel 다운로드. 다음 발표는 새 방으로 시작한다.

### 6.1 채팅 세부 동작 — 권장 초깃값

- 별명: 앞뒤 공백 제거, 2~20자. 같은 별명이 있으면 표시용 구분자를 붙이고 세션은 독립 유지.
- 메시지: 텍스트·일반 유니코드 이모지, 최대 500자. 첨부·링크 미리보기·개인 메시지는 초기 제외.
- 도배 방지: 세션별 2초당 1회 전송, 서버에서도 검사. 과도한 방 전체 유입 시 제한 상태와 재시도 시점을 안내한다.
- IP만으로 참여자를 식별하거나 제한하지 않는다. 행사장 공용 Wi-Fi의 여러 사용자를 고려한다.
- 신규 참여자는 해당 방의 최근 메시지부터 읽고, 이전 메시지는 제한된 단위로 추가 조회한다.
- 사용자가 이전 대화를 읽는 동안 강제 스크롤하지 않고 새 메시지 표시와 최신으로 이동 버튼을 제공한다.
- 내보낸 세션은 동일 방에 재입장·전송할 수 없다. 익명 참여자가 새 브라우저 세션을 만드는 우회까지 완전히 막는다고 약속하지 않는다.
- 삭제 메시지는 공개 본문과 키워드 집계에서 제외하고 Excel에도 원문을 포함하지 않는다. 삭제 시각·조치 기록은 분리한다.

### 6.2 발표 표시창

- 공개 표시창에는 대화·별명·키워드·필요한 접속 안내만 노출한다. 관리용 인증정보는 넣지 않는다.
- 최상위 고정 켜기/끄기. **뒤로 보내기는 최소화와 별도 동작**으로 정의하고 발표창 뒤에 배치되도록 Windows에서 검증한다.
- 뒤로 보내기나 클릭 통과 상태에서도 관리 화면·트레이·단축키로 표시창을 다시 불러올 수 있어야 한다.
- 투명도는 배경 20~100%, 기본 85%를 제안한다. 글자는 읽을 수 있게 유지하며 배경 투명도와 창 전체 투명도는 구현 단계에서 구분한다.
- 글자 크기 조절, 밝은/어두운 배경, 채팅 영역과 키워드 영역 비율 조절.
- 통합/분리 전환 시 데이터 연결은 앱에서 공유한다. 창이 늘었다고 청중 한도나 서버 연결을 불필요하게 소비하지 않게 한다.
- 창별 위치·크기·투명도·고정 여부 저장. 모니터 분리 시 화면 안으로 복구.
- 메시지 수신이 PowerPoint·Excel·브라우저의 키보드 포커스를 빼앗지 않게 한다.
- 전체화면 PowerPoint 및 화면 복제·확장 모드를 실기 검증한다. 확장 모드에서는 투사 대상 모니터에 표시창을 배치한다.
- 화면 복제나 전체 화면 공유에서는 관리 화면을 열면 청중에게 보일 수 있다. 앱 내부에서 관리 화면만 숨겨진다고 가정하지 않는다.
- 클릭 통과와 전체 창 숨기기는 편의 기능 후보이며 기본은 끔. 복구 수단을 먼저 검증한다.
- 기술 후보는 Electron의 창 제어 API다. 실제 Windows 동작과 뒤로 보내기에 필요한 보완은 별도 실험한다. [Electron 공식 문서](https://www.electronjs.org/docs/latest/api/browser-window)

### 6.3 키워드 메타데이터 — 권장 초깃값

- 한국어와 영문을 대상으로 정규화·토큰화·불용어 제외를 수행한다. 한국어 조사 처리 및 형태소 분석 도구는 실제 예문 정확도·배포 크기를 보고 선택한다.
- Unicode 정규화·영문 소문자화·문장부호 제거를 적용하고 숫자만 있는 토큰·URL·이모지 단독은 기본 제외한다. 영문 약어와 의미 있는 한 글자 명사는 예외 사전으로 지원한다.
- **기본 순위 점수는 해당 단어가 등장한 메시지 수**다. 한 메시지에 같은 단어를 반복해도 1회만 집계하며 화면에는 '언급 메시지 수'로 명시한다.
- 별도 지표로 서로 다른 참여 세션 수를 저장한다. 세션 수를 실제 사람 수로 표현하지 않는다.
- 집계 범위: 기본 최근 5분, 선택 시 방 전체. 최근 범위는 서버 시각 기준이며 새 메시지가 없어도 만료를 반영한다.
- 상위 10개 단어를 3초 간격으로 갱신하는 것을 제안한다. 키워드 전송은 표시용 구독자에만 보내 불필요한 전체 전송을 줄인다.
- 워드클라우드 글자 크기는 같은 점수를 반영하며, 단어가 계속 뛰어다니지 않도록 배치를 안정화한다. 동일 값은 일관된 정렬 규칙을 사용한다.
- 불용어 추가·특정 단어 숨김을 운영자가 설정할 수 있게 한다. 삭제 메시지는 다음 집계 주기 이내 제외한다.
- 데이터가 부족하면 빈 상태를 표시한다. 감정·사람의 의도·AI 요약 결과를 빈도 통계로 가장하지 않는다.
- 집계 규칙 버전과 범위를 통계·내보내기에 기록해 재현할 수 있게 한다.

### 6.4 기록과 Excel

- 방별 제목·개설/종료 시각·접속 세션 수·메시지 수·대화·키워드 통계 조회.
- Excel 시트: 발표 요약, 채팅 기록, 전체 키워드, 집계 기준. 시간은 한국 시간과 명시된 시간대로 내보낸다.
- 채팅 원문이 Excel 수식으로 실행되지 않도록 문자열 셀로 기록한다.
- 기록은 운영자가 삭제할 때까지 보관하는 것을 제안하되, 무료 저장 용량을 모니터링한다. 무제한 보관·클라우드 백업을 약속하지 않는다.
- 로컬 방식은 앱 데이터 폴더에 SQLite로 보관하고 별도 백업·복원을 제공한다. 클라우드 방식도 로컬 내보내기와 복구용 백업을 설계한다.
- 공개 채팅에 보낼 내용이 화면에 표시되고 발표 기록으로 보관된다는 간단한 안내를 입장 전에 제공한다.

## 7. 모바일 및 접근성 기준

- 360px 폭부터 가로 스크롤 없이 사용. 큰 화면에서는 읽기 폭을 제한한다.
- 본문 기본 16px 이상, 주요 터치 영역 44×44px 이상, 입력란에 눈에 보이는 레이블 제공.
- 모바일 키보드가 열린 상태에서도 입력·전송·오류 메시지를 확인할 수 있고 하단 안전 영역을 반영한다.
- iOS 한국어 조합 중 Enter로 메시지가 잘못 전송되지 않게 한다.
- 연결 상태는 색상과 문구로 표시하고, 전송 실패 시 작성 중인 내용을 보존한다.
- 워드클라우드와 같은 정보를 텍스트 순위로도 읽을 수 있다. 과도한 애니메이션을 줄이고 키보드 포커스를 표시한다.

## 8. 데이터 및 일관성 설계

최소 데이터: Room, ParticipantSession, Message, ModerationAction, KeywordRuleVersion, KeywordSnapshot, PresenterDisplaySettings.

- Room 상태: 준비 → 진행 → 종료. 종료는 신규 쓰기를 서버에서 차단한다.
- Message: 서버 발급 ID·방별 증가 순번·참여 세션·본문·수신 시각·삭제 상태·클라이언트 요청 ID.
- 전송 확인은 영구 저장 성공 이후에 보낸다. 요청 ID로 중복 전송을 방지하고, 마지막 수신 순번으로 재연결 이후 이력을 복구한다.
- 삭제·내보내기·종료도 재접속 이후 최신 상태를 적용한다. 내보낸 세션이 과거 토큰으로 다시 쓰지 못하게 한다.
- 클라우드의 여러 함수 인스턴스에 접속한 참여자들이 같은 방의 메시지를 빠짐없이 받도록 공유 이벤트 기록과 전파 계층을 둔다. 메모리 내 배열만으로 운영하지 않는다.
- 운영자 권한·방별 읽기/쓰기 권한·정원·본문 길이·전송 제한은 서버에서 검증한다.
- 공개 HTML 및 스크립트 실행을 허용하지 않는다. 운영 비밀정보는 청중 코드·QR·로그·내보내기에 포함하지 않는다.

## 10. 개발 순서

1. 운영 사전 실험: 사용 목적 확인, Vercel WebSocket·외부 저장소·다중 인스턴스 전파·재연결·사용량 계측. Windows 표시창 기능을 별도로 실험.
2. 무료 사용 조건 및 부하 평가 후 클라우드/로컬 운영 방식 확정. 로컬 선택 시 공개 주소와 터널 조건부터 확인.
3. 방 생성·QR·모바일 입장·실시간 텍스트·복구·기록 저장 구현.
4. 통합/분리 표시창·고정·뒤로 보내기·투명도·조작 복구 구현.
5. 키워드 순위·워드클라우드·삭제/내보내기·과거 조회·Excel 구현.
6. 실제 Windows와 모바일, 다른 네트워크, 200명 부하·한도 검증 후 첫 행사 준비.

초기 제외: 다수 발표자 서비스, 결제, 광고, 계정 기반 청중 인증, 파일/사진 전송, 개인 대화, 설문·투표, 생성형 AI 감정 분석·요약, 인터넷 없는 행사장 모드, 행사 도중 클라우드/로컬 자동 전환.

## 11. 남은 결정과 현재 상태

- 사용 목적은 개인·비상업적 발표나 모임으로 답변 완료. 회사 업무·유료 행사로 용도가 바뀌면 무료 플랜 적합성을 다시 확인한다.
- 발표 1회 길이·월 사용 횟수는 미정. 우선 60분 부하 프로필을 사용하고 실제 빈도에 맞춰 무료 예산을 다시 계산한다.
- 외부 저장소·동기화 제품, 로컬 터널, 인증 수단, Windows 지원 버전은 기술 실험 후 확정한다.
- 애플리케이션 구현·계정 설정·외부 배포·유료 결제·200명 부하 테스트는 아직 수행하지 않았다.
