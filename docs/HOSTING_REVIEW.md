# OnChat 무료 운영 검토

조사일: 2026-10-30 (한국 시간). 공식 문서를 확인한 결과이며 실제 계정·배포·성능을 검증한 결과는 아니다.

## 1. 결론

**Vercel Hobby로 실시간 채팅을 구현하는 것은 현재 기술적으로 가능하다.** 다만 200명 청중, 발표 기록 보관, 개인·비상업적 사용 조건, 외부 저장소 한도, 월 사용량을 함께 충족해야 무료 운영을 채택할 수 있다. 따라서 지금 단계의 결론은 '조건부 가능, 실측 미완료'다.

사용자는 개인·비상업적 발표나 모임 용도라고 답변했다. 사용 목적 조건은 충족하는 것으로 판단하며, Vercel 무료 구성의 기술 검증을 우선한다.

우선순위는 사용자의 요청대로 Vercel 무료 검증 → 불가하면 Windows 로컬 검증이다. 로컬 서버 역시 휴대폰 데이터 접속을 위해 공개 주소가 필요하므로 비용·접속성 문제가 저절로 사라지지는 않는다.

## 2. Vercel 확인 결과

| --- | --- | --- |

| 상태 공유 | 재접속이 다른 인스턴스로 갈 수 있음 | 외부 저장소와 인스턴스 간 이벤트 전파 필요 |

2026-10-20 정식 제공 발표를 확인했다. 검색에 남은 'Vercel은 WebSocket 서버를 지원하지 않는다'는 과거 안내를 현재 결론에 사용하지 않았다. [정식 제공 발표](https://vercel.com/changelog/websocket-support-is-now-generally-available)

표시창은 서버가 Vercel에 있어도 Windows 앱으로 구현한다. 웹 호스팅 무료 여부와 OS 창 제어 요구사항은 별개다.

## 3. 외부 무료 서비스 후보

### Upstash Redis

공식 무료 범위는 저장 256MB, 월 명령 50만 회, 대역폭 10GB다. 상태·이벤트 기록 저장 후보로 검토하되, 필요한 전달 방식과 실제 명령 소비를 먼저 실험한다. 영구 이력의 백업·용량 관리도 필요하다. [공식 요금표](https://upstash.com/pricing/redis)

접속자마다 초 단위로 저장소를 반복 조회하면 빠르게 소모된다. 클라우드 함수 인스턴스 단위 공유 구독·조회, 증분 이력, 일괄 집계 등을 검토한다. 지원 여부와 명령 과금 단위가 확인되지 않은 Pub/Sub나 블로킹 명령을 지원한다고 가정하지 않는다.

### Supabase Realtime

무료 동시 연결 200개, 초당 이벤트 100개, 월 메시지 200만 개다. 청중 200명 외 발표자 연결 여유가 없고, 전송량은 수신자에게 배포한 수까지 계산된다. 따라서 **200명 목표의 기본 실시간 계층으로 채택하지 않는다.** 데이터베이스만 별도 후보로 쓰는 것과 구분한다. [제한](https://supabase.com/docs/guides/realtime/limits), [이벤트 집계 기준](https://supabase.com/docs/guides/realtime/settings), [월 메시지 한도](https://supabase.com/docs/guides/realtime/pricing)

## 4. 비용 추산에 사용할 예시

아래는 산술 예시이며 요금 청구량·실제 처리 성능의 측정값이 아니다.

- 청중 200명, 60분, 방 전체 초당 2개 메시지 → 원본 메시지 7,200개.
- 전부 200명에게 배포하면 수신 전달 약 144만 회. 1KB 이벤트 가정 시 약 1.44GB의 본문 전송이며 프로토콜·이력·화면 파일·재전송 등은 별도다.
- 연결이 300초마다 교체된다고 단순 가정하면 청중 연결 시작은 시간당 약 2,400회다. 발표자·API·조기 종료·재시도는 별도다.
- 저장소 명령 수는 원본 메시지 수와 같지 않다. 검증·중복 방지·저장·배포·이력 복구·키워드·접속 상태까지 계측한다.
- CPU·메모리 사용량은 인스턴스 공유와 집계·전파 구조에 따라 달라진다. 연결당 고정 메모리 비용을 임의로 곱해 결론 내리지 않는다.
- 월 발표 횟수·길이가 미정이므로 '매달 무료'로 확정하지 않는다. 기존 계정 사용량도 합산한다.

## 5. 로컬 대안의 실현 조건

Windows 앱 + 로컬 HTTP/WebSocket 서버 + SQLite + 공개 HTTPS/WSS 연결 경로를 후보로 한다. 서버가 PC에 있으므로 PC의 전원·인터넷·업로드 성능이 운영 조건이다.

Cloudflare Quick Tunnel은 계정·도메인 없이 임시 주소를 만들 수 있지만 개발·테스트용이다. 동시 진행 요청 200개 제한, 가동시간 보장 없음, 재실행 시 주소 변경이라는 조건이 있다. 이를 '200명 실서비스 무료 보장'으로 해석하지 않는다. [공식 Quick Tunnel 문서](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)

정식 터널은 도메인·주소 구성·사용 조건·연결 한도·WebSocket 지원을 별도로 검토해야 한다. 임시 터널의 요청 제한을 일반 터널 전체 제한이나 WebSocket 참가자 한도로 단정하지 않는다. 공유기 포트 개방을 기본 절차로 정하지 않으며 공개 경로에는 청중 기능만 노출한다.

## 6. 채택 기준

1. 개인·비상업적 사용 조건에 해당하고, 무료 저장소와 함께 200명 부하·복구·월 사용량 검증을 통과하면 Vercel 방식 채택.
2. 사용 조건이 맞지 않거나 무료 한도·실기 검증에 실패하면 Windows 로컬 방식의 공개 연결·부하·복구를 검증.
3. 로컬도 요구사항을 충족하지 못하면 무료 200명 지원은 미달성으로 남긴다. 허락 없이 유료 서비스로 전환하거나 같은 Wi-Fi 전용으로 바꾸지 않는다.

현재 완료: 공식 문서 조사, 개인·비상업적 사용 목적 확인, 인터뷰 요구사항 정리, PRD 1.0 작성.

현재 미완료: 실제 계정 잔여량 확인, 운영 저장소·터널 확정, 애플리케이션 구현, 외부 배포, 200명 부하·실제 Windows 검증.
