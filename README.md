# 수다온 · SudaOn

QR로 청중을 초대하고, 별명 하나로 실시간 대화를 나누는 발표 도구입니다. 채팅과 인기 키워드를 PowerPoint·Excel·웹브라우저 위에 표시합니다.

- 지정 저장소: [dalbitfox/sudaon](https://github.com/dalbitfox/sudaon)
- 지정 웹 주소: [sudaon.vercel.app](https://sudaon.vercel.app)
- 제품 요구사항: [PRD](docs/PRD.md)
- 구현·검증 상태: [IMPLEMENTATION](docs/IMPLEMENTATION.md)
- 무료 운영 조사: [HOSTING_REVIEW](docs/HOSTING_REVIEW.md)

## 사용하기

### Windows 발표자

Windows 휴대용 실행 파일은 `npm run desktop:win`으로 생성하며, GitHub Actions도 Windows 빌드를 제공합니다. 빌드 결과를 받은 사용자는 실행 파일을 열면 됩니다. 개발 환경에서는 `release/수다온 0.1.0.exe`에 생성됩니다.

1. 앱을 열고 **이 컴퓨터에서 시작하기**를 누릅니다.
2. **새 발표 만들기**에서 발표 제목을 입력합니다.
3. 공개 주소가 연결된 상태에서 QR을 청중에게 보여줍니다. PC 전용 주소의 QR에는 공개 주소 연결 안내가 표시됩니다.
4. **발표 화면 띄우기**에서 채팅과 키워드를 한 창 또는 두 창으로 엽니다.
5. 표시창 설정에서 배경 투명도·글자 크기·최상위 고정·뒤로 보내기를 조절합니다.
6. 발표가 끝나면 **발표 종료**를 누릅니다. **발표 기록**에서 대화·통계를 다시 확인하거나 Excel로 내려받습니다.

앱 메뉴 **수다온 → 온라인 수다온 열기 / 이 컴퓨터의 로컬 모드 열기**로 서버 위치를 전환합니다. 온라인 모드는 Vercel 초기 설정이 끝난 이후 사용할 수 있습니다. 채팅방과 기록은 선택한 서버별로 구분되며 자동 이동하지 않습니다.

- `Ctrl + Alt + Space`: 발표자 화면·표시창 복구
- `Ctrl + Alt + H`: 표시창 숨기기
- 관리 창의 닫기 버튼: 트레이로 숨기며 서버는 계속 실행
- 트레이 **수다온 완전히 종료**: 앱과 로컬 채팅 서버 종료

표시창은 메시지가 와도 발표창의 키보드 포커스를 가져오지 않습니다. Windows의 실제 PPT 전체화면·다중 모니터 동작은 실기 확인이 필요합니다. 현재 실행 파일은 코드 서명이 없는 개발 빌드입니다.

### 청중

QR 스캔 → 별명 입력 → **입장하기** → 채팅. 회원가입과 공통 입장번호는 없습니다. 메시지·별명은 전체에 공개되고 발표 기록으로 보관됩니다. 보낼 수 없는 상태에서는 작성 중인 내용을 지우지 않습니다.

## 배포

Vercel 프로젝트가 이 GitHub 저장소를 사용하도록 연결하고 Framework는 **Vite**, Root Directory는 저장소 루트로 설정합니다. 빌드·설치·라우팅 설정은 `vercel.json`에 있습니다.

**실제 비밀 값을 코드·Git·이슈·채팅에 넣지 마세요.** 프로젝트 소유자가 Vercel의 환경 변수 설정 화면에서 다음 값을 직접 관리합니다.

| 환경 변수 | 용도 |
| --- | --- |
| `SUDAON_OWNER_PASSWORD` | 발표자 로그인 암호. 12자 이상 |
| `SUDAON_SESSION_SECRET` | 세션 서명용 임의 비밀 값. 32자 이상 |
| `UPSTASH_REDIS_REST_URL` | 외부 영구 저장소의 HTTPS REST 주소 |
| `UPSTASH_REDIS_REST_TOKEN` | 서버 전용 저장소 접근 권한 |
| `SUDAON_PUBLIC_URL` | 선택. 청중에게 표시할 공개 서비스 주소 |

이 값들은 브라우저 번들에 포함하지 않습니다. 저장소·인증 설정이 없으면 온라인 방 생성이 비활성화되며, 메모리에 임시 저장하는 가짜 온라인 모드로 대체하지 않습니다. 환경 변수 설정 후 새 배포가 필요합니다.

Redis는 REST `EVAL`, `LRANGE`, `RPUSH`, `SMEMBERS`, `ZADD` 등을 지원해야 합니다. **클라우드 상태는 Redis의 이벤트 기록에 저장**하고 함수 인스턴스마다 증분으로 읽습니다. 쓰기는 순번 비교 후 원자적으로 추가해 동시 쓰기 손실을 막습니다. 별도의 Pub/Sub 지원을 가정하지 않습니다. 인스턴스별 활성 방 폴링도 무료 명령 한도에 포함되므로 실제 월 사용량 검증이 필요합니다.

Vercel의 함수 실행 제한으로 WebSocket이 닫히면 자동 재접속하고 최신 기록을 받습니다. 부하·실행 시간·저장소 한도를 실제 배포에서 검증하기 전 200명 무료 운영을 보장하지 않습니다. [Vercel 공식 WebSocket 안내](https://vercel.com/docs/functions/websockets)

### 로컬 서버를 청중에게 공개하기

Windows 앱은 로컬 서버를 기본 실행합니다. 인터넷의 청중에게 공개하려면 별도의 HTTPS/WSS 터널이 필요합니다. `localhost` QR만으로 휴대폰 데이터에서 접속할 수 없습니다.

서버 운영자는 공개 주소를 `SUDAON_PUBLIC_URL`로 설정할 수 있습니다. 일반 Node 서버의 기본 주소는 `127.0.0.1:4173`이며, Windows 앱은 빈 포트를 선택합니다. 터널 연결은 앱이 자동으로 생성하지 않습니다. 채택한 터널의 200명 연결·한도·안정성 검증은 아직 필요합니다.

공개 프록시는 `/api/owner/local`을 외부에 노출하지 않도록 차단해야 하며 `Host`·클라이언트 전달 헤더를 보존해야 합니다. 서버도 외부 Host 또는 전달 헤더가 있는 로컬 운영자 등록을 거부합니다. 공개 주소에는 청중 기능만 제공하고 운영자 등록 경로를 우회 허용하지 마세요.

## 개발

Node.js 24 이상 권장. 최초 설치는 개발자 환경에서 수행합니다.

```bash
npm ci
npm run dev
```

로컬 접속: `http://127.0.0.1:4173`. 브라우저에서 **이 컴퓨터에서 시작하기**로 운영자 세션을 만듭니다.

```bash
npm run build
npm start
npm test
npm run test:load
npm run desktop:win
```

`test:load`는 운영 주소에 부하를 보내지 않고 격리된 로컬 서버·DB를 만듭니다. 기본 200명, 30초, 초당 2개 목표 및 추가 20개 메시지를 시험합니다. `SUDAON_LOAD_SECONDS=300` 등으로 시험 시간을 조절할 수 있습니다. JSON 결과는 Git에서 제외된 `artifacts/load-report.json`에 저장합니다.

로컬 DB는 일반 Node 실행 시 `data/sudaon.sqlite`, Windows 앱은 사용자 앱 데이터 폴더에 저장됩니다. 종료된 발표도 기록을 유지합니다. 영구 기록 삭제·DB 복원 UI와 자동 백업은 초기 버전에 포함하지 않았습니다. Excel 다운로드는 DB 백업과 구분합니다.

## 구현 범위

- 최대 200명 정원 제어·별명 중복 구분·전송 제한·재시도 중복 방지
- WebSocket 실시간 전달·자동 재접속·누락 이력 복구·이전 대화 조회
- 운영자 권한 검사·메시지 삭제·세션 내보내기·방 종료
- 최근 5분/방 전체 키워드, 순위/워드클라우드, 제외 단어
- SQLite/Redis 이벤트 저장, 실제 `.xlsx` 다운로드
- Windows 투명 표시창·분리/통합·최상위/뒤로 보내기·위치 저장·트레이·단축키

한국어 집계는 **조사 제거 휴리스틱**이며 정교한 형태소 분석이 아닙니다. 별명은 실명 인증이 아니고 참여 세션 수는 사람 수와 다를 수 있습니다. 내보내기는 해당 세션을 차단하며 새 브라우저를 이용한 익명 재입장을 완전히 방지하지는 않습니다.
